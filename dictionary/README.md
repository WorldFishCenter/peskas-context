# Peskas data dictionary

One description of the data the Peskas dashboards publish: what each collection holds, what each metric means, how its values combine, and whether it is recorded or estimated. AskFish's catalog is generated from it, and checks compare it with the dashboard and with production.

## Files

| File | What it holds |
|---|---|
| `portal.odcs.json` | The `portal-prod` collections the dashboard reads, as an [ODCS v3.2.0](https://bitol-io.github.io/open-data-contract-standard/) data contract: grain, fields, types, units, the measure names each carries, one server per country |
| `metrics.json` | Each measure: meaning, unit, total or average and its weight, recorded or estimated and by which method, its twin, the versions that brought it, caveats |
| `metrics.schema.json` | The JSON Schema `metrics.json` follows |
| `askfish.json` | What only AskFish needs: which collections it may query and under which id, its pages and scope modes, row limits, and Hamza's own rules and Kenya BMU datasets, copied as they were |
| `semantic-catalog.json` | Generated by `build.py`: AskFish's catalog, in the shape its contract 1.0 checks |
| `odcs-json-schema-v3.2.0.json` | ODCS's own schema, for the check |

## How it works

`build.py` turns the three source files into `semantic-catalog.json`; `sync.py` copies it into the dashboard (`packages/api/src/askfish/semantic-catalog.json`), as `consumers.json` lists. The dashboard keeps its own copy, so its build depends on no other repo.

- **When coasts changes** what `export_portal()` writes (a collection, column or metric), whoever makes the change updates `portal.odcs.json` and `metrics.json` in the same work, then runs `python build.py`, `python sync.py` and the dashboard's tests.
- **When the dashboard changes** a metric in `packages/domain/src/metrics.ts` or its English texts, update `metrics.json` to match.
- **To let AskFish use more**: add a collection to `askfish.json`'s `datasets`. AskFish rejects any field its contract doesn't know, so new kinds of facts need Hamza first.

`build.py` and `sync.py` need only Python. `check.py` needs `jsonschema`, `uv` fetches it.

## Checks

- `python sync.py --check`: the dashboard's copy is the generated one.
- `uv run --with jsonschema check.py`: both files are valid against their schemas; every measure a collection carries is defined, and the reverse; `semantic-catalog.json` is up to date; the dashboard's `metrics.ts` (read with Node) and English `metric-<key>-title` and `-unit` texts agree. `--self-test` checks the check.
- `Rscript ../peskas-context/dictionary/prod_check.R`, run from a country pipeline: read-only against that country's `portal-prod`, the columns, measure names and one row per grain match `portal.odcs.json`.
- `python golden.py`: asks AskFish, through a running dashboard (`--url`, default `http://localhost:3001`), questions the pages answer, and compares. One AI call each; `--page-only` prints the page's figures alone.

The first two run by themselves every Monday and on each change here, against the dashboard's `dev` (`.github/workflows/dictionary.yaml`). `prod_check.R` runs after every portal export in the Kenya, Zanzibar and Mozambique pipelines, reading this folder from `main`. A failure turns the run red.

The dashboard combines figures, for its pages and for AskFish, with the same code (`packages/api/src/lib/cells.ts`); AskFish asks for them (`aggregateOver`) and doesn't redo the maths. `metrics.json` says how each measure combines, and `check.py` checks the dashboard agrees.
